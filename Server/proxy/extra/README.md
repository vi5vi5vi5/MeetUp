# Соседи на этом же сервере

Сюда кладутся `server`-блоки других сервисов, которые живут на той же
машине и должны отвечать по своим доменам через этот же nginx.

nginx подхватывает отсюда всё по шаблону `*.conf` (см. `include` в
`../nginx.conf`). Каталог монтируется с хоста только на чтение, поэтому
правки переживают и пересборку образа, и `git pull` — в отличие от
самого `nginx.conf`, который при обновлении затирается.

## Как добавить сервис

1. Положить сюда его `server`-блок. У Ferry готовый лежит в
   `Ferry/Server/proxy/ferry.conf.example`:

   ```bash
   cp ../../../../Ferry/Server/proxy/ferry.conf.example ferry.conf
   $EDITOR ferry.conf          # вписать своё имя в server_name
   ```

2. Добавить это имя в сертификат и перезапустить прокси:

   ```bash
   cd ../..                    # в Server/
   ./tools/update.sh --force --extra-domain fferry.ru
   ```

   Сертификат будет один на все имена сразу: и на домен MeetUp, и на
   домены соседей. Продлевается он тоже один, обычным циклом в контейнере
   `proxy`.

3. Убедиться, что контейнер соседа виден по сети. Он должен быть
   подключён к сети этого проекта и отзываться по имени, которое стоит в
   `proxy_pass`. Для Ferry это делает его же `update.sh`:

   ```bash
   cd ../../../Ferry/Server
   ./tools/update.sh --force --behind-proxy server_default
   ```

## Чего сюда не надо

Блоков для самого MeetUp: он описан в `../nginx.conf` и работает как
сервер по умолчанию — то есть отвечает на всё, что не подошло ни под один
`server_name` отсюда. Поэтому соседям обязательно нужен явный
`server_name`, иначе они просто никогда не сработают.
